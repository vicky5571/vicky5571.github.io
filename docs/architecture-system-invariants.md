# Architecture & System Invariants

## 1. System Overview & Architectural Invariants

### 1.1 Stack Profile & Core Technologies
- **Runtime**: Node.js v26.8.1 (Native ES Modules, `"type": "module"`)
- **Primary Framework**: React 19.0.0 (`react`, `react-dom`) with Vite 6.1.0
- **Build & Bundler**: Vite 6.1.0 with `@vitejs/plugin-react` 4.3.4 and manual chunking (`react`, `motion`, `icons`)
- **Asset Optimization**: `vite-plugin-image-optimizer` 2.0.3 with `sharp` 0.35.3 (WebP/AVIF compression, multipass SVG)
- **Styling System**: Tailwind CSS 3.4.17 + PostCSS 8.5.3 + Autoprefixer 10.4.20
- **Theme & Design Tokens**: Custom dark ink aesthetic:
  - Palette: `ink (#10100f)`, `milk (#f5f1e8)`, `acid (#d5ff3f)`, `flame (#ff5e3a)`, `cyan (#36d7ff)`, `plum (#7a5cff)`
  - Typography: `Playfair Display` (serif display), `Inter` (sans-serif body), `JetBrains Mono` (monospace code)
- **Animation & Visuals**:
  - `framer-motion` 13.1.1 (`m`, `AnimatePresence`, `useScroll`, `useSpring`, `useTransform`, `useMotionValueEvent`)
  - Icons: `lucide-react` 0.475.0 & `@tabler/icons-react` 3.46.0
  - Canvas 2D: Custom waterpaint ink drop physics engine in `MimoHero.jsx`
- **Deployment Target**: GitHub Pages via `gh-pages` 6.3.0 (`npm run deploy`), static output directory `dist/`
- **Testing Engine**: Node.js native test runner (`node:test`, `node:assert/strict`)

### 1.2 Routing & Viewport Architecture
- **Single Page Application (SPA)**: Linear landing page experience with smooth scroll navigation (`#work`, `#experience`, `#contact`).
- **Scroll Synchronization**: Two-tier scroll monitoring:
  1. `useSpring`-smoothed scroll progress tracking for global progress indicator and navbar backdrop blur.
  2. Debounced `IntersectionObserver` with `-45% 0px -45% 0px` root margin to track active viewport sections without jitter at section boundaries.
- **Entry Pipeline**:
  - `index.html` -> `src/main.jsx` (React 19 `createRoot`) -> `src/App.jsx`

## 3. Persistence Architecture

- **Client State Hydration**:
  - The application is a pure client-side static bundle.
  - Zero external database or backend server dependencies; no server-side rendering (SSR) hydration mismatch risks.
  - Initial load executes synchronously in browser DOM via `ReactDOM.createRoot`.
- **Caching & Asset Delivery Strategy**:
  - Static bundle outputs (`dist/assets/*.js`, `dist/assets/*.css`) contain content hashes generated by Vite/Rollup for immutable caching (`Cache-Control: max-age=31536000, immutable`).
  - Images in `public/img/` are pre-converted to modern WebP format with predefined dimensions to prevent Cumulative Layout Shift (CLS).
- **Backend Synchronization**:
  - Current architecture is decoupled from direct database writes.
  - Any future contact form or analytics integrations MUST follow an optimistic update pattern with local fallback and graceful degradation if offline.

## 4. Codebase Invariants & Strangler Pattern on God Files

### 4.1 Monolithic God Files Identified

| File | Lines | Responsibilities Mixed | Status / Target |
| :--- | :--- | :--- | :--- |
| `src/App.jsx` | 968 | Data constants, Header navigation, Work grid, Method timeline, Contact form, Footer | **God File**: Target < 250 lines via component extraction |
| `src/components/MacbookScroll.jsx` | 742 | 3D canvas/CSS transform, hundreds of individual SVG keycap components | **High Complexity**: Keep isolated; extract keycap primitives |
| `src/components/ui/macbook-scroll.jsx` | 630 | Redundant variant of `MacbookScroll.jsx` | **Duplicate**: Consolidate into single component |
| `src/components/MimoHero.jsx` | 330 | Canvas 2D particle simulation, resize observers, Hero copy | **Coordinator**: Keep canvas logic separated from UI layout |

### 4.2 Invariant Rules for Future Modularity
1. **Single Source of Truth (SSOT)**: All core domain schemas and validators must reside in `src/types/index.js`.
2. **Decomposition Protocol**: Extract `Header`, `Work`, `Method`, `Contact`, and `Footer` out of `src/App.jsx` into modular subcomponents inside `src/components/sections/`.
3. **Data Segregation**: Extract raw project and experience arrays out of UI component files into dedicated data modules (`src/data/portfolioData.js`).
4. **Fast Test Execution**: Every business logic helper and data transformer MUST have a corresponding sub-second unit test in `tests/` executed via `node --test`.
